# Datasetツリーのカラム階層表示（Issue #10）

## 概要
v1.6.3 では、Dataset ツリー配下の各テーブルについて、Databases ツリー（`id="db-tree"`）の Tables 配下と同等にカラム一覧をツリー表示する。

あわせて、表示した Dataset カラムに対して以下を Databases ツリーのカラムと同等に提供する。
- コンテキストメニュー（同一メニュー項目・同一機能）
- ドラッグ&ドロップでクエリエディタへカラム名を挿入する操作

## 背景
現状は Dataset ツリーでテーブル単位までは辿れるが、テーブル配下のカラム構造が表示されず、Databases ツリーと操作導線が分断されている。

そのため、SQL 作成時に Dataset 側のみ操作手順が増え、学習コストと操作コストが上がっている。

## 対象範囲
- 対象 UI:
  - Dataset ツリー（`id="dataset-tree"`）
  - クエリエディタ（`id="query-editor"`）
- 対象機能:
  - Dataset テーブル配下のカラムツリー描画
  - カラムノードのコンテキストメニュー
  - カラムノードの D&D（エディタ挿入）
- 主な想定反映先:
  - `src/js/components/Sidebar.vue`
  - `src/js/App.vue`
  - `src/css/app.scss`

## 非対象
- Databases ツリー側（`id="db-tree"`）既存仕様の変更
- Dataset 登録/削除フローそのものの仕様変更
- SQL パーサー/フォーマッターの仕様変更

## 機能要件
1. Dataset ツリーの各テーブルノード配下に、該当テーブルの全カラムを子ノードとして表示する。
2. カラムノードの表示順は Databases ツリーと同じ規則に揃える（既存規則がある場合はそれに従う）。
3. カラムノードのコンテキストメニューは Databases ツリーのカラムと同じ項目を表示し、同じ結果を返す。
4. カラムノードをドラッグしてクエリエディタへドロップした場合、Databases ツリーのカラム D&D と同一フォーマットで SQL が挿入される。
5. テーブルの展開/折りたたみ時にカラムノードが正しく追従し、表示崩れや重複描画が発生しない。
6. Dataset の再読み込み・再登録・削除後も、カラムツリーが最新状態に同期される。

## 非機能要件
- 既存の D&D 可視フィードバック（許可/不許可）を Dataset カラムノードでも維持する。
- Databases ツリーと Dataset ツリーで操作感が不一致にならないこと（同一操作で同一結果）。
- 既存 E2E セレクタ方針（`#dataset-tree` / `#query-editor`）を壊さないこと。

## 受け入れ条件
- AC-1: Dataset ツリーで任意テーブルを展開すると、配下にカラム一覧がツリー表示される。
- AC-2: 表示された Dataset カラムノードの右クリックで、Databases ツリーのカラムと同一のコンテキストメニューが表示される。
- AC-3: AC-2 の各メニュー項目実行結果は、Databases ツリー側カラム実行時と同一動作になる。
- AC-4: Dataset カラムをクエリエディタへ D&D すると、Databases ツリー側と同じ形式でカラム名が挿入される。
- AC-5: Dataset の再読み込み・削除・再登録後も、カラム表示と操作（右クリック/D&D）が正常に機能する。
- AC-6: 既存の Databases ツリーのカラム右クリック/D&D 回帰が発生しない。

## テスト計画
### E2E（Playwright）
- ケース1: Dataset テーブル展開でカラムノードが表示されることを確認。
- ケース2: Dataset カラム右クリックでメニュー表示を確認。
- ケース3: Dataset カラムの各メニュー実行結果が Databases ツリー側と同等であることを確認。
- ケース4: Dataset カラムを `#query-editor` に D&D し、期待文字列がエディタに挿入されることを確認。
- ケース5: Dataset を再登録後に再度ケース1-4が成立することを確認。

### 回帰
- Databases ツリーの既存カラム操作（右クリック/D&D）関連の既存シナリオが通過すること。
- 既存の Dataset 取り込み・表示シナリオが通過すること。

## 実装メモ
- Dataset カラムノードの識別情報（dataset名/テーブル名/カラム名）を、既存の Databases カラム処理へ橋渡しできる形で揃える。
- 右クリックと D&D の処理経路は可能な限り共通化し、片側のみ仕様差分が生じない構造にする。
